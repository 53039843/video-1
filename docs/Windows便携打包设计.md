# Windows 便携发行设计

## 发行策略

本程序采用 **轻量 EXE 启动器 + 同目录便携运行时** 的发行结构，而不采用“所有模型、CUDA、Python 和 FFmpeg 压进单个 EXE”的方式。当前开发虚拟环境约 3.37 GB，其中包含 EasyOCR、Torch、Pandas、Matplotlib 等验证或未启用组件；直接单文件封装会显著增加启动解压时间、杀毒误报概率与维护成本。便携目录只保留正式流水线所需依赖，启动器本身为单个 Windows EXE，用户双击即可完成硬件探测、端口选择、服务启动、URL 显示和浏览器打开。

| 层级 | 内容 | 设计目的 |
|---|---|---|
| `VideoLocalizer.exe` | 原生启动器 | 双击入口、环境探测、URL展示、服务管理 |
| `app` | 后端源码、控制面板、模型和默认配置 | 可独立更新业务逻辑 |
| `runtime` | 精简 Python 3.11 环境及项目依赖 | 目标电脑不需要安装 Python |
| `tools` | FFmpeg、FFprobe | 目标电脑不需要安装媒体工具 |
| `data` | SQLite、下载、输出、任务临时目录 | 业务数据和程序文件分离 |
| `logs` | 启动与服务日志 | 故障诊断与版本追踪 |

## 自动兼容策略

启动器会检测 Windows 版本、64 位架构、可用内存、NVIDIA 驱动、FFmpeg 能力和端口占用。若检测到 NVIDIA GPU 且运行库可加载，后端优先使用 CUDA；若无 NVIDIA GPU、显存不足或 CUDA 初始化失败，正式流水线会记录原因并自动回退 CPU INT8。视频编码优先使用 NVENC；便携版本还会补充软件编码回退，确保非 NVIDIA Windows 电脑仍能完成任务。

| 检测项 | 兼容决策 |
|---|---|
| NVIDIA GPU 可用 | ASR 使用 CUDA FP16，成片优先 NVENC |
| NVIDIA GPU 不可用 | ASR 使用 CPU INT8，成片使用 libx264 |
| 8790 端口被占用且是本程序 | 复用服务并直接打开 URL |
| 8790 被其他程序占用 | 自动寻找 8791–8899 的空闲端口 |
| FFmpeg/模型/运行时缺失 | 启动器窗口显示明确缺失文件并写入日志 |
| 服务启动超时 | 保留窗口、显示日志路径，不静默退出 |
| 浏览器无法自动打开 | 窗口持续显示可复制 URL |

## 数据与安全边界

发行包不会包含开发过程中的 `downloads`、`output`、`local_jobs` 和历史 SQLite 数据，也不会打包用户视频。AI 网关密钥不应硬编码到启动器或源码；分发版使用同目录 `.env.local` 或 Windows 环境变量读取。首次打包可保留现有本机配置用于当前电脑使用，但对外分发前必须移除真实密钥并提供配置模板。

> 便携模式的“任意 Windows 电脑兼容”是指支持 Windows 10/11 64 位，并能在 NVIDIA GPU 与纯 CPU 两种路径间自动选择。Windows 7、32 位系统及不支持当前 Python/FFmpeg 的旧系统不在保证范围内。

## 成功标准

冷启动验证必须在不调用系统 Python、不依赖开发虚拟环境、显式使用便携 FFmpeg 的条件下完成。启动器应输出硬件摘要、实际服务地址、数据目录和日志路径；浏览器访问健康接口应返回 `ok`；刷新控制面板后历史记录应从便携数据目录中的 SQLite 恢复。
