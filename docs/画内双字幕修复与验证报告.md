# 画内双字幕修复与验证报告

本次修复已完全撤销“扩展画布并增加底部黑色字幕带”的错误方案。当前实现维持源视频 **720×1280** 原始分辨率和原始画面边界，保留视频内已有的白色中文硬字幕，并将黄色马来语译文以顶部居中锚点烧录在原字幕下方。正式流水线与验证样片使用同一套 ASS 布局逻辑。

> 本项目中的“双字幕”定义为：原视频硬字幕原样保留；目标语言译文在同一画面内水平居中，紧邻对应原字幕下方；不扩展画布，不增加黑色底栏，不重复烧录原文。

| 验证项 | 结果 | 证据 |
|---|---:|---|
| 原视频分辨率保持 | 通过 | ASS 画布使用源高度，FFmpeg 无 `pad` 和额外渲染高度 |
| 黑色字幕带彻底移除 | 通过 | 正式流水线无黑色填充、无安全带逻辑 |
| 译文水平居中 | 通过 | ASS 使用 `Alignment=8`，逐段事件使用 `\\an8\\pos(360,y)` |
| 原字幕底边跟踪 | 通过 | 五帧持久字形投票，亮色核心加暗色描边约束 |
| 字号稳定 | 通过 | 24 段译文字号统一为 32 px，间距统一为 4 px |
| 数据完整性 | 通过 | 24 条记录，无重复索引、无非法时长、无缺失字段 |

## 实现说明

字幕定位不再采用整条视频单一固定基线，也不直接相信单帧亮色区域。每个字幕段抽取五个时间点，先用多数投票保留跨帧持续存在的字形，再要求亮色字形附近具有暗色描边，以过滤人物皮肤、衣服、产品反光等高亮误检。高置信度且位于主字幕轨道合理范围内的测量会被保留，因此源硬字幕真实下移时，译文也会随之下移；超出合理范围的孤立测量则回退到主轨道。

| 文件 | 作用 |
|---|---|
| `subtitle_detector.py` | 多帧持久字形检测、暗描边约束、逐段原字幕底边跟踪 |
| `real_media_pipeline.py` | 正式流水线原尺寸 ASS 烧录、水平居中动态坐标 |
| `build_stable_track_sample.py` | 使用同一布局生成本次验证样片 |
| `validate_production_pipeline.py` | 正式处理路径回归断言 |
| `validate_track_data.py` | pandas 数据质量检查和轨道位置图 |

## 视觉复核结论

14.5 秒是本次关键回归点。原视频白色硬字幕位于约 `y=936..972`，修复前黄色译文错误地位于其上；修复后黄色译文被放到白字下方且未遮挡白字。4 秒、40 秒和90 秒代表帧也均形成稳定的画内上下双字幕，没有黑色扩展块、切边或横向偏左。

69 秒原视频同帧本来没有白色硬字幕，成片只显示黄色“A-Qian”。这不是布局遮挡问题，而是现有 ASR/硬字幕时间对齐数据在字幕切换边缘存在约帧级偏差。当前改造范围解决的是布局与轨道定位；若要求每一帧都必须同时出现原硬字幕和译文，还需另做硬字幕出现/消失时刻的逐帧二分校准。

## 交付结论

正式控制面板调用的真实媒体流水线已经接入本次修复，不再使用黑块方案。当前样片可用于直接检查画内双字幕效果，配套 CSV、JSON、位置图和代表帧保留了可复核证据。生产回归报告中的所有断言均通过。
